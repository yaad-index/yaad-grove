What it is

An engine, not a bot.

You have a community — a podcast, a magazine, a hobby group, a person documenting their own work — and a knowledge base about it. yaad-grove answers from that base and its tools, and refuses anything outside them: smart enough to understand the question, never allowed out of the bounds you designed. Point the same engine at a different config and it becomes a different bot — no single community is baked in.

Grounding on the answering side, mirrored by isolation on the data side.

Key features

Guardrails that are structural, not hopeful.

Grounded by design

A tiny tool surface, a scoped system prompt, and an explicit refusal path leave the model nowhere to freelance from.

Config-driven

A bot is vault + tools + scope + transport; the engine stays generic. A different config makes a different bot — nothing hard-coded.

Consent is a hard gate

Before opt-in the bot only sends a consent prompt — it does not answer, and records nothing the user said.

Quarantined chatter

Community chatter is logged to an isolated store the answering bot never reads — grounding mirrored by data isolation.

Layered limits

Per-user override > tier > default, all under a global spend ceiling that a restart cannot reset.

Any OpenAI-compatible model

Swap providers by changing the base URL, model name, and key — a hosted gateway or a local one, no code change.
